# Marathon du Jeu 2.0

Application Windows pour tenir le Marathon du Jeu — 24 heures de jeu de société : des joueurs
anonymes, une carte à code par joueur, des sessions où l'on badge, des tirages au sort où chaque
session badgée est une chance.

La version 2.0 reprend le logiciel de l'édition 2025 et le rend **prêt pour l'édition à venir** :
deux phases de travail, 22 lots livrés, 96 tests. Tout ce qui suit est nouveau depuis la 1.1.

## Installation

Décompressez `marathondujeu-v2.0-windows.zip` dans un dossier et lancez `marathondujeu.exe` — le
dossier entier est nécessaire (`data\`, les DLL). Aucune installation, aucun réseau.

Les données vivent dans `%APPDATA%\com.saroc\marathondujeu`. **Une base de la version 1** (dans
`%LOCALAPPDATA%\com.example\marathondujeu`) est **reprise par copie au premier lancement** ;
l'ancien fichier reste en place. Les données d'avant sont mises à niveau à l'ouverture : numéros
des joueurs, catégories des groupes, numéros des tirages.

## Ce qui change pour l'organisateur

### Les cartes

- **Générateur de cartes paramétrable** : image de fond, planche (cartes par ligne et par page,
  largeur, marges, espaces, orientation), position et taille du code et du numéro, fonds et
  couleurs — tout en millimètres, tout enregistré avec l'événement. Aperçu rapide à chaque
  réglage, aperçu PDF et impression sur demande.
- **Protection des cartes** : un code secret propre à l'événement entre dans le code de chaque
  carte ; une carte d'un autre événement, ou fabriquée, est « invalide ». La protection se
  récupère depuis une carte imprimée si la base est perdue.
- Les joueurs sont **anonymes** : chacun est un numéro de carte. On indique combien de cartes on
  imprime, les joueurs manquants sont créés.

### Les sessions et le badgeage

- Les **sessions se génèrent d'elles-mêmes** depuis l'événement (début, fin, durée, intervalle),
  avec un **aperçu** dans l'éditeur : nombre, première, deuxième, dernière. Changer les horaires
  les recrée — confirmation demandée s'il y a déjà des badgeages.
- **Retour de scan sur toutes les pages**, dans la barre du haut : au repos, ce qu'un scan fait
  ici ; après, ce qui s'est passé — vert ou rouge. Les notifications sont des toasts en haut au
  centre.
- Page d'une session : **Présents** et **Absents** (ceux qui ont badgé une autre session), les
  billes s'animent au badgeage ; **badgeage manuel** hors horaire ; **numéro** pour badger sans
  carte ; **mode suppression** (le scan retire, bouton *Retirer* sur chaque bille).
- Liste des sessions : la session ouverte en couleur, les passées grisées, « n présents »,
  légende.
- **Fiche joueur** : son QR code, son bonus (« + » / « − », aussi sur les cartes de la liste),
  ses sessions badgées en cartes cliquables en badgeage manuel. Sans jeton, sa bille est grise :
  il n'est pas dans l'urne.

### Les tirages

- Un tirage **se prépare, s'enregistre, se lance une seule fois** ; lancé, il se consulte en
  lecture seule et **se copie** — la copie exclut ses gagnants, pour retirer avec les mêmes
  règles. Compteur de jetons dans l'urne, sélecteur de sessions en grille.
- Les gagnants forment un **groupe** « Gagnants du tirage … », marqué d'un trophée dans les choix
  d'un tirage.
- Chaque tirage a un **numéro dans son événement** (« Tirage N°1 », « N°2 »…), stable, qui suit
  l'événement d'un poste à l'autre.

### Les groupes

- Groupes faits main (habitués, une table…) pour **exiger ou exclure** des joueurs d'un tirage :
  ajout par scan ou par numéro, mode suppression, renommage, suppression refusée tant qu'un tirage
  s'en sert.

### Les événements

- **Fichier de sauvegarde par événement** : choisissez un fichier, l'application le réécrit toute
  seule à chaque modification (joueurs, badgeages, groupes, tirages, image des cartes).
  *Ouvrir un fichier de sauvegarde* ramène l'événement entier — après un poste mort, ou sur un
  autre poste. Un événement déjà présent se remplace après confirmation.
- **Fermer un événement** : depuis la liste ou son éditeur, avec confirmation ; tout ce qui s'y
  rattache disparaît, son fichier de sauvegarde reste.
- Sans événement en base, l'application guide vers sa création ; sans événement choisi, elle le
  demande.
- Fermer un éditeur modifié demande *Revenir* ou *Quitter* — plus de saisie perdue par un clic à
  côté.

### L'aide

- Un **« i »** en haut à droite de chaque page lance un **pas à pas sur l'écran** : voile, zone
  mise en lumière, une ou deux phrases par pas — adapté aux données (liste vide, session ouverte,
  tirage effectué…). Des petits « i » à infobulle sur les champs qui demandent un mot ; des
  légendes dans les écrans.
- Un **Guide** dans le rail : le parcours d'une édition en six temps, illustré par les vrais
  composants de l'écran, avec un bouton vers chaque page.

### L'application

- Une **icône** (un dé et un pion), le nom « Marathon du Jeu » partout où Windows l'affiche.
- La douchette est lue par l'application elle-même : une carte protégée est reconnue quelle que
  soit la disposition du clavier.

## Sous le capot

- Base **Isar** sur le fork `isar_community` 3.3 (l'original n'est plus maintenu), Flutter 3.47,
  Riverpod 3, freezed 3, go_router 18 ; `flutter analyze` à zéro.
- **96 tests** sur une vraie base Isar temporaire, dont un **parcours de bout en bout** qui joue une
  édition entière sur l'application — 76 gestes relevés dans `docs/gestes.md`, chacun avec son
  test.
- Corrections du modèle et du tirage (égalité des objets, liens des tirages, gagnants sans joueur).
- Le schéma n'est jamais détruit : les champs nouveaux s'ajoutent, les données d'avant sont
  migrées à l'ouverture.

## Limites connues

- Seule la cible **Windows** est construite.
- L'heure de la dernière sauvegarde, dans l'éditeur d'événement, ne se rafraîchit pas tant que
  l'éditeur reste ouvert.
- Le format du fichier de sauvegarde (`.marathon.json`, version 1) est celui de cette version ;
  une version future le lira, l'inverse n'est pas garanti.
